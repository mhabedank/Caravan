# Caravan 0.1.0

The first release: a declarative pipeline from one YAML manifest to an int8 model, its C array and
its interface contract, for microcontrollers. Candidates are tagged `v0.1.0rcN`; `v0.1.0` follows
once the `pace-cnn` port below has run.

## What it does

- `validate` and `render` check a manifest and print it as the pipeline will use it, without
  reading data or loading a framework.
- `build`, `train`, `quantize` and `export` run the stages: the data stage derives what the data
  says, the model is built from a template (`mlp` or `conv1d`), checked against every target
  board's flash and RAM before any training, trained, converted to int8 and gated on what the
  conversion cost in accuracy, then exported with an operator resolver, one runner skeleton per
  board and an interface contract that names every input and output with its position, shape,
  scale and zero point.
- Every stage is cached by what it reads, so a change re-runs only what it affects.
- A dataset can name its own split per record (`dataset.split.column`), so subjects, vehicles or
  sessions stay on one side of it.
- The training framework's output is kept in `framework.log` in the run directory, not on the
  console.

## Where it runs

| Part | Python | Install |
|---|---|---|
| core: `validate`, `render`, `templates`, `boards` | 3.13, 3.14, 3.15 | the wheel, no extras |
| reading and running exported models (`verify` extra) | 3.13, 3.14 | `[verify]` |
| building, training, converting (`train` extra) | 3.13 | `[train,verify]` |

Linux and macOS. Installed from the GitHub release of the tag; not on the package index.

## Known limits

- Training and conversion need Python 3.13: TensorFlow publishes no stable wheel for anything
  newer (2.22.0rc0 is still a candidate, checked 2026-10-23).
- `export` needs the training extra even when training and quantization are cached; a machine with
  only the runtime cannot export a model trained elsewhere.
- Inputs are not scaled. Columns of very different ranges share one int8 input scale, and on the
  synthetic example the model with derived (sorted) labels fails the int8 gate, 0.75 trained
  against 0.50 quantized (feature 006, research R11). The example pins its labels for that reason.
- Memory and flash figures are lower bounds computed from the model, not measurements on a board.
- One input and one output per model.
- Windows never overlap.

## Change notes

One breaking manifest change since development began: `caravan/v0` → `caravan/v0.1`, with the edit
an author makes by hand, in `docs/manifest-changes.md`. Before 1.0.0 nothing is migrated; a
manifest in another form is refused with the version this build reads.

## Release gate

The constitution's gate before a framework release, and where each item was shown:

- semantic versioning: `0.1.0rc1`, PEP 440;
- a change note for every breaking schema change: see above;
- the pilot manifest green end to end: the `release.yml` run of the tag (linked when the release is
  made).
